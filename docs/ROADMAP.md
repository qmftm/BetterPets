## 지금까지 확정된 것

빌드하고 코드를 짜면서 **실제로 확인한** 것들입니다. 문서만 보고 정한 게 아니에요.

- **빌드가 통과합니다** — JDK 25로 BetterModel 3.4.1 API에 대해 실제 컴파일, 단위 테스트 141개 통과
- **캐리어 엔티티는 보이지 않는 `Mob`** — `ItemDisplay` 대신 고른 이유는 자체 히트박스가 있어서예요.
  모델에 히트박스 본(`b_`)이 없어도 우클릭이 먹힙니다
- **BetterModel API 격리** — `BetterModelRenderer` 가 그 API를 import 하는 유일한 파일입니다
- **탑승은 `ArmorStand` + Paper `Input`** — `allowFlight` 를 안 쓰므로 비행 권한이 샐 위험 자체가 없어요
- **선택적 연동은 리플렉션** — DiscordSRV·Floodgate 가 없어도 빌드되고 돌아갑니다.
  상속이 필요한 PlaceholderAPI 만 예외로 컴파일 의존(`provided`)을 겁니다

## 다음에 직접 확인할 것

코드로는 더 할 게 없고, **테스트 서버에서 눈으로 봐야 하는** 것들이에요.

1. **모델이 실제로 뜨는가** — `.bbmodel` 하나를 넣고 `/petadmin egg` → 우클릭 → `/pet summon` 순으로
2. **트래커 누수가 없는가** — `/petadmin debug` 의 세 숫자(활성 펫 / 캐리어 / 트래커)가 일치하는지
3. **추종 이동이 자연스러운가** — 계단·언덕에서 끊기지 않는지, 텔레포트 폴백이 과하지 않은지
4. **탑승·비행 조작감** — 벽 슬라이딩과 하차 안전 처리가 실제로 먹히는지
5. **Bedrock 변환** — 모델 하나로 GeyserModelEngine 파이프라인을 끝까지 통과시켜 보기
6. **연동이 실제로 붙는가** — `/petadmin debug` 의 연동 줄에서 상태 확인
7. **여러 마리 소환** — `max-active` 를 2 이상으로 두고, 한 마리에 탔을 때 나머지가 제자리에 남는지

전체 수동 체크리스트는 [DESIGN.md의 테스트 절](DESIGN.md#테스트)에 있습니다.

> **Bedrock 검증은 일찍 하는 게 좋습니다.** BetterModel 3.4.1 + GeyserModelEngine + MC 26.2 조합은
> 검증된 적이 없어요. 모델을 여러 개 만든 뒤에 안 되는 걸 알면 텍스처부터 다시 작업해야 합니다.
> 첫 모델이 자바에서 뜨자마자 그 하나로 Bedrock 변환을 시험해 보세요.

## 각 단계의 완료 조건

1. 기능이 테스트 서버에서 동작한다
2. 해당 범위의 단위 테스트가 통과한다
3. [수동 체크리스트](DESIGN.md#테스트)를 통과한다
4. 문서를 갱신하고 커밋·푸시한다
